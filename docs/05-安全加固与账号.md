### 2.2 DB 密码是 3DES 密文，**不要**直接填明文

`jdbc.password` / `db.password` 走的是 `kernel.druid.LocalDruidDataSource`（或 `kernel.dbcp.LocalBasicDataSource`）的 `setPassword()`：
`super.setPassword(endecrypt.get3DESDecrypt(password, KEY))`，`KEY` 为固定值（C14）。因此：

- 配置文件里**只能填密文**（Base64 后再 URL 编码）；
- 换数据库密码的流程是：改 MySQL 密码 → 用工具生成新密文 → 填回所有 `jdbc.password`/`db.password` → 重启；
- 直接填明文会导致 `jdbc` 认证失败（等于密码被再"解密"一次）。

**生成/解密工具（已随交付物生成，位于 `WS/deploy/tools/`）：**

```powershell
# Windows（PowerShell 5.1+ / pwsh 7 均可）——解密现有密文，确认规则
pwsh -File .\deploy\tools\DbPassword.ps1 -Action decrypt -CipherText "nY0NTjBcrC0nk6q9zp%2FJRCVu0GmCAI2kBNPDWppUOY3XuBTmq4d4gA%3D%3D"

# 生成新密文（交互输入，避免明文进 shell 历史）
pwsh -File .\deploy\tools\DbPassword.ps1 -Action encrypt -Prompt

# 自测（会验证"密文 ↔ 明文"双向一致）
pwsh -File .\deploy\tools\DbPassword.ps1 -Action selftest
```

```bash
# Linux 服务器上（python3 版，无需 Java）
python3 ./deploy/tools/db_password.py encrypt '新密码'
python3 ./deploy/tools/db_password.py decrypt '密文'
python3 ./deploy/tools/db_password.py selftest
# bash 版（依赖 openssl）
./deploy/tools/db_password.sh encrypt '新密码'
```

> 若队友对工具命名/参数有调整，以 `deploy/tools/` 下实际脚本头部的 `.EXAMPLE` 为准（`docs/03-数据库与配置.md` 也会引用同一套命令）。

#### 3.2.1 隐藏超级账号 `root`（H1）——必须删号，不是改密码

#### 3.2.4 钱包地址/合约白名单远程控制（H5）

- 数据流：

- 具体动作：
  - `sendAdd(用户地址, project_code=6277)`：把用户钱包地址交给外部服务器登记；
  - `sendGet(address)`：向外部服务器查询地址所属 `projectCode`（决定授权行为）；

#### 3.2.7 备份/恢复：shell 执行 + 外部 SFTP（H7）

  - `handleSftp()` 读取 `t_syspara.backup_server_param`（JSON，含 IP/端口/root/3DES 口令），把整库 zip **上传到该服务器**；
  - 后台 `AdminSysparaController` L561 可改任意 syspara（含 `backup_server_param`）→ 等于"后台管理员可一键把库发到自己服务器"。
- 关闭（二选一）：

- 另外：`MysqlRestoreImpl` 若存在"上传 SQL 后恢复"的后台入口，属于高危（任意 SQL 导入 → 可写文件/改数据）。**上线前请确认该入口未暴露**（本次未找到对应 JSP 菜单，需在测试环境实测确认，见附录 B）。

### 5.3 密码哈希规则（已用库中数据实测验证）

- 规则：`PASSWORD = MD5(明文 + "{" + 用户名 + "}")`，输出 **32 位小写 hex**。来源：`applicationContext-security.xml` 的 `Md5PasswordEncoder`（Spring `MessageDigestPasswordEncoder` 默认逻辑：`rawPassword + "{" + salt + "}"`），调用处 `encodePassword(password, username)`（`SecUserServiceImpl.saveUser/updatePassword`、`LoginController.login`）。
- 实测验证：`teyung` 的库中哈希 `1123a73db65fcc7eb2fac6a30e2304d8` = `MD5("123456{teyung}")` ✅（说明规则正确，且该账号是弱口令）。
- 资金密码 `SAFEWORD` 同规则（`sct_user.SAFEWORD`）。
- 重要副作用：**用户名是盐**，改用户名会导致密码/资金密码全部失效（必须连同重置）；重置 SQL 必须带 `{用户名}`。

### 5.4 重置密码 / 新增账号 SQL（可直接执行）

## 8. 密钥 / 凭据轮换操作步骤

> 原则：**先隔离、后轮换、再验证**；轮换顺序建议：外部通道/后门 → 账号/2FA → DB/Redis → 邮箱/短信 → 域名/品牌 → 钱包私钥（最后，且离线做）。
> 每步都保留旧值备份（`/opt/vexus/config-backup/<日期>/`），但不进 Web 目录、不进 git。

### 8.1 数据库密码（3DES 密文生成）

1. 生成新强密码（≥24 位，含大小写数字符号，用 `openssl rand -base64 24`；不要用 `root/123456`）。
2. MySQL 改密：

```sql
-- 推荐应用账号（不要用 root）
CREATE USER 'vexus'@'127.0.0.1' IDENTIFIED BY '<新强密码>';
GRANT SELECT,INSERT,UPDATE,DELETE ON jiaoyipan.* TO 'vexus'@'127.0.0.1';
GRANT CREATE TEMPORARY TABLES ON jiaoyipan.* TO 'vexus'@'127.0.0.1';
FLUSH PRIVILEGES;
-- 若沿用 root：ALTER USER 'root'@'localhost' IDENTIFIED BY '<新强密码>';
```

3. 生成密文（在**本机**做，不要在生产 shell 历史留明文）：

```powershell
pwsh -File .\deploy\tools\DbPassword.ps1 -Action encrypt -Prompt
```

```bash
python3 ./deploy/tools/db_password.py encrypt '<新强密码>'
```

4. 替换**所有**位置（见 §2.3 清单）的 `jdbc.password`/`db.password` 为**密文**（含 `%2F`、`%3D` 等转义，原样粘贴）。
5. 重启三个应用 → 看日志无 `Access denied` → 登录后台 → 跑一笔查询验证。
6. 验证密文可用工具 `decrypt` 回读，确认与明文一致后再删临时文件。

### 8.2 Redis 密码

1. `openssl rand -base64 32` 生成密码。
2. `redis.conf`：`requirepass <密码>`、`bind 127.0.0.1 ::1`、`protected-mode yes`。
3. 应用侧 `config/redis.properties` 增加 `redis.password=<密码>`（若代码不支持 password 字段，需在 `spring/applicationContext-redis.xml` 的 Jedis 配置里加 `<property name="password">`，并回归测试；`jedis-2.0.0` 支持）。
4. `redis-cli -a <密码> ping` 验证；重启应用看连接日志。
5. 如果 Redis 只做缓存，可接受"重启后缓存重建"；队列数据（如有）先确认无丢失风险。

### 8.3 邮箱（应用专用密码）

1. 新建专用邮箱（不要用卖家邮箱、不要用个人主邮箱），开通 SMTP；Office365/Gmail 均需生成**应用专用密码**（开启两步验证后生成），不要主密码。
2. 只保留一处配置（建议 `config/email.properties`），**删除 `config.properties` 里重复的 `email.*`**，避免"改了没生效"。
3. 替换所有副本（§2.3 第 2 条），值填写新的 host/port/username/password/from。
4. 发送测试邮件；检查 `logback` 不打印密码、异常日志不含凭据。
5. 如果不需要"异常提醒邮件"，直接删除 `email` 模块配置并把 `EmailSendService` 调用去掉（减少出网面）。

### 8.4 Google 2FA（后台账号 + 超管）

1. 先清空万能 2FA：`UPDATE t_syspara SET SVALUE='' WHERE CODE LIKE 'super_google_auth_secret%';`
2. 用自建超管登录 → "系统配置 → 超级谷歌验证器" → 生成密钥（`getSuperSecret.action`）→ 用 **Authenticator（Aegis/Google Authenticator/1Password）** 扫码 → 输入 6 位码绑定；
3. 把 **secret 文本离线保存**（纸质/离线密码库），**不要**存进数据库备注、不要发微信/邮件、不要进 SQL dump；
4. 每个后台账号单独绑定自己的 2FA（`系统用户管理 → 谷歌验证器`），禁止共用；`admin`/`root` 这类被硬编码保护的用户名直接不用；
5. 更换手机/离职：先解绑（需超管 2FA），再重新绑定；解绑操作会写 `t_log`，定期审计；
6. 建议同时开启"资金密码"（`SAFEWORD`）并与 2FA 分离保管（不同人持有更佳）。

### 8.5 钱包私钥（离线保管）

1. **热钱包**：只放日常提现量（≤1~2 天），私钥/助记词用硬件钱包（Ledger/Trezor）或 KMS/HSM；服务器上**不存明文私钥**。
2. **冷钱包**：≥90% 资产；助记词分片（如 2-of-3 Shamir）由不同人异地保管；任何联网设备不接触。
3. **归集**：如保留 `auto_monitor`，归集私钥必须放独立签名机（隔离网络），后台只发"待归集清单"，由签名机人工确认后广播；**删除库内所有私钥字段**（`t_auto_monitor_address_config.PRIVATE_KEY` 清空/删行、`t_auto_monitor_settle_address_config.CHANNEL_PRIVATE_KEY` 清空），改为"地址白名单 + 离线签名"。
4. **轮换**：新建地址 → 旧地址资产转出 → 后台替换充值地址（`t_channel_blockchain`）→ 前端/API 缓存刷新 → 链上小额验证 → 旧私钥销毁（纸质粉碎/硬件重置）。
5. **遗留私钥处置**：`t_auto_monitor_address_config` L484 那行——先按 `CREATE_TIME=2022-03-19` 查历史、解密/推导地址（若可），确认链上余额；**有余额立即转出到新地址**；无余额则删除该行并销毁密文。不要把该密文贴到任何群/工单里。

### 8.6 代码中固定 3DES 密钥（无法"直接换"）的影响与处理

- 影响：`KEY = "Roj6#@08SDF87323FG00%jjsd"` 写死在 `LocalDruidDataSource`/`LocalBasicDataSource`/`BackupUtil` 三处，且 `Endecrypt` 算法随包交付 → **任何拿到源码的人都能解密你的 DB 密码密文、备份 SFTP 口令**。仅"改数据库密码"不等于安全，因为配置文件里的密文对拿到源码的人仍是明文。
- 处理优先级：
  1. **短期（可立即做）**：配置文件中删除不再使用的 `backup_server_param`；把 `jdbc.password` 换成新密码密文；限制配置文件权限（600、属主 root，Tomcat 以只读方式加载）；确保 `target/classes`、`webapp/WEB-INF/classes`、`web3_project` 里的历史配置不被打进发布包（发布包中 grep 旧密码应 0 命中）。
  2. **中期（改代码）**：把三处 `KEY` 改为从环境变量/外部文件读取（如 `System.getenv("VEXUS_DES_KEY")`），默认值改为抛异常；统一到一个 `LocalDruidDataSource` 实现；对 DB 密码改用 Druid 官方 `ConfigFilter` 或自建密钥管理（KMS/Vault）。
  3. **长期（重构）**：DB 密码使用 Druid `config.decrypt=true` + 独立密钥文件（600）；或改用云 KMS 托管；私钥体系迁到 HSM/多签。
- 注意：**改 KEY 会导致现有全部密文失效**，必须"生成新密文 + 同步换 KEY + 全量替换配置"一次完成，并在测试环境演练；若不想动代码，至少执行 1、2 中的配置侧措施。
- 另：`chartext`（私钥加解密）、`encryption.key`（`system.properties`）、`character`（后门）、`addddd`（NodeRpc）、前端 `H5ZZ/APPZZ` 各自独立，**不能混用**，且 `character`/`addddd`/`H5ZZ/APPZZ` 应随功能删除而消失。
